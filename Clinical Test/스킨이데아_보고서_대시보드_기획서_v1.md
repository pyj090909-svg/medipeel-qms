## 0. 결론 요약 (Executive Summary)

전사 마케팅·RA·품질구매가 함께 쓰는 "검색·열람 + KPI 모니터링" 중심의 가벼운 웹 대시보드를 만든다. 데이터는 **구글시트가 원본(Source of Truth)**, 화면은 **HTML 단일 페이지**, 둘을 잇는 다리는 **Google Apps Script Web App**으로 구성한다. 어느 브라우저에서 열든 최신 데이터가 보이고, 품질구매팀은 대시보드 상에서 직접 신규 보고서를 입력하면 구글시트에 즉시 반영된다. PDF 보고서는 임베드 없이 SharePoint 링크 새 탭 열기로 충족한다.

MVP는 **검색·필터·KPI 카드 + 신규 입력 폼**까지 포함하고, 영문 미발행 트래킹·이력 변경 로그 같은 부가 기능은 Phase 2로 미룬다.

## 3. 데이터 모델 — 통합 마스터 시트 설계

원본 4개 시트를 한 장의 마스터 시트로 합치고, 정규화된 컬럼을 추가한다. 정규화 컬럼은 **사람이 채우지 않고 수식·스크립트가 채운다**(데이터 품질 보장).

### 3-1) 마스터 시트 컬럼 정의 (`마스터_보고서` 시트)

| 컬럼 | 컬럼명 | 타입 | 입력 방식 | 비고 |
|---:|---|---|---|---|
| A | 보고서ID | 텍스트 | 자동 (시험코드와 동일) | PRIMARY KEY |
| B | 연도 | 숫자 | 자동 (시트명 → 4자리) | 2023~2026 |
| C | 시험차수No. | 숫자 | 수동 | 원본 No. 그대로 |
| D | 제품명 | 텍스트 | 수동 | 줄바꿈 제거 후 trim |
| E | 시험코드 | 텍스트 | 수동 | `KIDS-XXX-SKE` |
| F | 시험제목 | 텍스트 | 수동 | 따옴표 정리 |
| G | 시험종류 | 텍스트 | **자동 (URL 폴더명 추출)** | 효능/흡수도/항균/설문 |
| H | 효능태그 | 텍스트(쉼표) | **자동 (시험제목 키워드 매칭)** | 모공,보습,리프팅 등 다중 |
| I | 국문발행일 | 날짜 (YYYY-MM-DD) | **자동 정규화** | 6자리 숫자/한글 모두 변환 |
| J | 국문링크 | URL | 수동 | SharePoint 원본 |
| K | 영문발행일 | 날짜 (YYYY-MM-DD) | **자동 정규화** | 없으면 빈 값 |
| L | 영문링크 | URL | 수동 | 없으면 빈 값 |
| M | 영문상태 | 텍스트 | **자동 (수식)** | "발행완료" / "미발행" |
| N | 등록일 | 타임스탬프 | 자동 (입력 시각) | 입력 추적 |
| O | 등록자 | 이메일 | 자동 (Apps Script 세션) | 입력자 추적 |

### 3-2) 발행일 정규화 규칙

발행일 포맷이 섞여 있어 마이그레이션 스크립트로 한 번에 정리한다.

 3-2-1) **6자리 숫자(YYMMDD)**: `230125` → `2023-01-25`
   - 변환 로직: 앞 2자리 → `20XX`, 가운데 2자리 → 월, 끝 2자리 → 일
 3-2-2) **한글 날짜("M월 D일")**: `"3월 10일"` + 시트명 `2025년` → `2025-03-10`
   - 변환 로직: 정규식 `(\d+)월\s*(\d+)일` 매칭 + 시트명 연도 결합
 3-2-3) **빈 값**: 그대로 빈 값 유지 (영문보고서 미발행 등)
 3-2-4) **검증**: 1900-01-01 < 발행일 < 시스템 오늘날짜+30일 범위 체크. 벗어나면 마이그레이션 로그에 기록

### 3-3) 자동 태깅 규칙

**시험종류 (G열)** — 국문링크 URL의 폴더명에서 추출

```
URL 디코딩 후 정규식: /\d+\.\s*\d+_([^_]+)_/
매칭 결과 → 효능 / 흡수도 / 항균 / 설문인체적용시험 / (없으면) "기타"
```

**효능태그 (H열)** — 시험제목 텍스트에서 사전 매칭

키워드 사전(우선순위 높은 순):

```
모공, 보습, 리프팅, 진정, 탄력, 쿨링, 색소, 주름, 자극, 흡수, 여드름,
민감, 미백, 윤기, 광채, 안티에이징, 노화지수
```

매칭된 키워드를 쉼표(,)로 연결하여 H열에 저장. 검색·필터의 핵심 축이 된다.

### 3-4) 보조 시트

 3-4-1) `설정_효능키워드` — 효능태그 사전을 시트로 분리해서, 비개발자도 키워드 추가·삭제 가능
 3-4-2) `설정_시험종류` — 시험종류 매핑 규칙 (URL 폴더명 → 표준명)
 3-4-3) `로그_변경이력` — Apps Script가 입력·수정 이벤트를 추가만(append-only)으로 기록
 3-4-4) `원본_2023~2026` — 마이그레이션 전 백업 (수정 금지)

## 4. 시스템 아키텍처

### 4-1) 3계층 구조

```
┌──────────────────────────────────────────────────────────┐
│  [Layer 1] 사용자 브라우저 (Chrome / Edge / Safari)        │
│   - HTML 단일 페이지 (검색·필터·KPI·결과 테이블·입력 폼)   │
│   - Vanilla JS + Tailwind(CDN). 외부 빌드 없음             │
└────────────────┬─────────────────────────────────────────┘
                 │  fetch(JSON)
                 ▼
┌──────────────────────────────────────────────────────────┐
│  [Layer 2] Google Apps Script Web App (백엔드)            │
│   - doGet : 마스터 시트 → JSON 반환 (캐시 30초)            │
│   - doPost: 신규 입력 / 수정 처리 + 자동 태깅 + 로그 기록   │
│   - 인증  : Google 계정(@medipeel.com 도메인 화이트리스트)  │
└────────────────┬─────────────────────────────────────────┘
                 │  SpreadsheetApp API
                 ▼
┌──────────────────────────────────────────────────────────┐
│  [Layer 3] Google Sheet (Source of Truth)                 │
│   - 마스터_보고서 / 설정_효능키워드 / 설정_시험종류 /         │
│     로그_변경이력 / 원본_2023~2026                          │
└──────────────────────────────────────────────────────────┘
```

### 4-2) 실시간 동기화 전략

"어느 브라우저에서 열든 최신 데이터"를 만족하기 위해 다음 3중 전략을 쓴다.

 4-2-1) **GET 시 캐시 무효화**: 대시보드 열 때마다 `fetch(GAS_URL + '?ts=' + Date.now())` 형태로 GET → 항상 최신
 4-2-2) **POST 직후 즉시 갱신**: 입력 폼 제출 성공 시 클라이언트에서 즉시 GET을 한 번 더 호출 → 화면 자동 새로고침
 4-2-3) **백그라운드 폴링(옵션)**: 화면이 열려있는 동안 60초마다 GET → 다른 사람이 입력한 데이터도 반영
   - 주의: 폴링은 Apps Script 호출 한도(분당 ~30회/사용자)를 잡아먹으므로 60초가 적정선

### 4-3) 권한 모델

| 역할 | 구글시트 권한 | 대시보드 동작 |
|---|---|---|
| 품질구매팀 (편집 그룹) | 마스터 시트 편집 가능 | 검색·열람 + 신규 입력 + 수정 |
| 마케팅·RA·기타 부서 | 마스터 시트 보기 권한 | 검색·열람만 (입력 폼 비활성) |
| 외부(비메디필 계정) | 접근 차단 | 로그인 페이지로 이동 |

권한 판정은 Apps Script에서 `Session.getActiveUser().getEmail()`로 도메인·그룹 확인. 프론트엔드는 GET 응답에 `userRole` 필드를 받아 입력 폼 노출 여부를 토글한다.

### 4-4) 보안·운영 고려사항

 4-4-1) **시트 공유 범위**: 마스터 시트 자체는 도메인 내부 공유로 제한. 외부 공개 절대 금지
 4-4-2) **Apps Script 배포**: "Execute as: Me" + "Who has access: 메디필 도메인 전체" 설정
 4-4-3) **에러 처리**: doPost 실패 시 사용자에게 구체적 메시지 + `로그_변경이력`에 실패 원인 기록
 4-4-4) **링크 무결성**: URL은 SharePoint 도메인(`medipeel-my.sharepoint.com`)만 허용하도록 입력 검증
 4-4-5) **백업**: 매일 새벽 1시 트리거로 마스터 시트를 별도 백업 시트에 복제(최근 30일 유지)

### 5-2) 상단 KPI 카드 (4개) — 한눈 모니터링

| 카드 | 계산식 | 색상 |
|---|---|---|
| **총 보고서** | `COUNT(마스터)` | 진청 |
| **올해 발행** | `COUNT(국문발행일 BETWEEN 올해 1/1 ~ 12/31)` | 그린 |
| **영문 보유** | `COUNT(영문상태='발행완료')` + `(N%)` | 옐로 |
| **영문 미발행** | `COUNT(영문상태='미발행')` | 그레이 |

KPI는 현재 적용된 필터 결과 기준으로 동적 갱신(전체 171 → 필터링 후 47 등). 카드를 클릭하면 해당 조건이 필터로 자동 적용되는 단축 동작을 둔다.

### 5-3) 검색·필터 바

 5-3-1) **통합 검색창**: 제품명 · 시험코드 · 시험제목을 OR 조건으로 부분 일치 검색. 한글 자모 분리 검색 미지원(MVP에서는 불필요)
 5-3-2) **연도 드롭다운**: 전체 / 2023 / 2024 / 2025 / 2026
 5-3-3) **시험종류 드롭다운**: 전체 / 효능 / 흡수도 / 항균 / 설문인체적용시험 / 기타
 5-3-4) **효능태그 멀티 선택**: 모공 · 보습 · 리프팅 · 진정 · 탄력 · 쿨링 · ... (체크박스 다중 선택, OR 조건)
 5-3-5) **영문상태 드롭다운**: 전체 / 발행완료 / 미발행
 5-3-6) **필터 초기화 버튼**: 모든 필터 리셋
 5-3-7) **URL 동기화**: 필터 상태를 쿼리스트링에 반영(`?year=2024&tag=모공,보습`) → 링크 공유 시 동일 화면 재현

### 5-4) 결과 테이블

 5-4-1) **표시 컬럼(MVP)**: No., 제품명, 시험코드, 시험제목(요약 80자), 시험종류, 효능태그, 국문발행일, 링크 버튼
 5-4-2) **링크 버튼**: 국문(파란 버튼), 영문(회색 버튼, 미발행 시 비활성). 클릭 시 SharePoint URL을 새 탭으로 열기 (`target="_blank" rel="noopener"`)
 5-4-3) **정렬**: 컬럼 헤더 클릭으로 정렬. 기본은 발행일 내림차순(최신이 위)
 5-4-4) **페이지네이션**: 50건/페이지. 171건 기준 4페이지로 충분
 5-4-5) **빈 결과 안내**: "조건에 맞는 보고서가 없습니다" 메시지 + 필터 초기화 안내
 5-4-6) **로딩 상태**: 스켈레톤 UI(회색 줄무늬) 1초 이내 표시
 5-4-7) **수정(편집 권한자)**: 행 우측에 ✏️ 아이콘 → 입력 폼과 동일한 모달이 데이터 채워진 상태로 열림

### 5-5) 신규 입력 폼 (모달)

품질구매팀만 우측 상단 `+ 신규 입력` 버튼이 보이고, 클릭 시 모달이 뜬다.

**입력 필드**:

 5-5-1) 시험차수No. (숫자, 필수) — 동일 연도 중복 시 경고
 5-5-2) 제품명 (텍스트, 필수)
 5-5-3) 시험코드 (텍스트, 필수, `KIDS-XXX-SKE` 형식 검증)
 5-5-4) 시험제목 (멀티라인, 필수)
 5-5-5) 국문발행일 (날짜 피커, 필수)
 5-5-6) 국문링크 (URL, 필수, SharePoint 도메인 검증)
 5-5-7) 영문발행일 (날짜 피커, 선택)
 5-5-8) 영문링크 (URL, 선택)

**자동 처리**:
 5-5-9) 보고서ID = 시험코드 (자동)
 5-5-10) 연도 = 국문발행일 연도 (자동)
 5-5-11) 시험종류 = 국문링크 URL에서 추출 (자동)
 5-5-12) 효능태그 = 시험제목에서 키워드 매칭 (자동)
 5-5-13) 영문상태 = 영문링크 유무 기준 자동
 5-5-14) 등록일·등록자 = 자동

**저장 동작**:
 5-5-15) 저장 → Apps Script doPost → 마스터 시트 append → 로그 기록 → 모달 닫기 → 화면 GET 재호출 → 결과 테이블 즉시 반영
 5-5-16) 실패 시 모달 유지 + 에러 메시지(필드 단위 하이라이트)

### 5-6) 반응형·접근성

 5-6-1) 데스크톱 우선 (1280px 이상 최적). 노트북 1366px도 지원
 5-6-2) 태블릿/모바일은 KPI 카드 2x2, 테이블은 가로 스크롤로 대응
 5-6-3) 색상은 Tailwind 표준 팔레트 사용. 색맹 친화적(빨강·녹색 단독 의미 부여 금지, 아이콘 병행)

## 6. 개발 로드맵 (바이브 코딩 작업 순서)

### 6-1) Phase 1 — MVP (목표: 1~2일 코딩 세션)

이 순서대로 빌드하면 막힘 없이 끝낼 수 있다. 순서가 곧 의존 관계다.

 6-1-1) **STEP 1. 데이터 마이그레이션** (2시간)
   - 신규 구글시트 생성 → 시트명 `메디필_인체적용시험_보고서_DB`
   - 원본 엑셀 4개 시트를 `원본_2023~2026`으로 복제 (백업)
   - Apps Script로 마이그레이션 함수 1회 실행 → `마스터_보고서` 시트 생성 + 발행일 정규화 + 자동 태깅
   - 마이그레이션 결과 검증: 171건 카운트, 발행일 빈 값/이상값 점검

 6-1-2) **STEP 2. Apps Script Web App 백엔드** (3시간)
   - `Code.gs` 작성: `doGet`(JSON 반환), `doPost`(append + 자동 태깅 + 로그)
   - 권한 판정 함수: `getUserRole(email)` → 'editor' / 'viewer' / 'denied'
   - Web App으로 배포 → URL 확보
   - Postman/curl로 GET·POST 동작 검증

 6-1-3) **STEP 3. HTML 대시보드 프론트엔드** (4시간)
   - 단일 HTML 파일 (Tailwind CDN + Vanilla JS)
   - GET → JSON → 메모리 보관 → 필터·검색·정렬은 클라이언트에서 처리(171건은 클라이언트 처리로 충분)
   - KPI 카드 4개, 검색 바, 필터 드롭다운, 결과 테이블, 페이지네이션 구현
   - 입력 폼 모달 + POST 연결 + 즉시 GET 재호출

 6-1-4) **STEP 4. 통합 테스트·배포** (1시간)
   - 편집자 계정 / 뷰어 계정 / 외부 계정으로 각각 동작 확인
   - 신규 입력 → 다른 브라우저에서 새로고침 → 즉시 노출되는지 확인
   - HTML 파일을 Apps Script Web App으로 함께 서빙(`HtmlService`) 또는 사내 정적 호스팅에 업로드

### 6-2) Phase 2 — 확장 (Phase 1 안정화 후)

 6-2-1) **영문 미발행 워크플로**: 미발행 건 별도 위젯 + 진행 상태(요청중/번역중/검수중/발행완료) 컬럼 추가
 6-2-2) **변경 이력 뷰**: `로그_변경이력` 시트를 대시보드에서 시간순 조회
 6-2-3) **CSV/엑셀 내보내기**: 현재 필터 결과를 다운로드
 6-2-4) **알림 자동화**: 신규 입력 시 슬랙/이메일 알림 (Apps Script Trigger)
 6-2-5) **관련 데이터 연계**: 포장재 평가 대시보드(이전 기획)와 제품 키 통합 → 한 화면에서 양쪽 조회
 6-2-6) **외부 공유 모드**: 거래처용 읽기 전용 토큰 발급 화면

### 6-3) 개발 시 사용할 핵심 라이브러리·기술

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Vanilla JS + Tailwind CDN | 빌드 도구 불필요, 단일 HTML로 배포 가능 |
| 차트 | Chart.js CDN | KPI 보조용. MVP는 카드 숫자만으로도 충분 |
| 백엔드 | Google Apps Script | 구글시트 네이티브 API, 무료 호스팅, 인증 내장 |
| 인증 | 구글 워크스페이스 SSO | 메디필 도메인 화이트리스트로 즉시 권한 분리 |

### 6-4) 검증 체크리스트 (배포 전)

 6-4-1) 마이그레이션 후 마스터 시트 건수 = 171 (원본 합계와 일치)
 6-4-2) 발행일 모든 행이 YYYY-MM-DD 형식 또는 빈 값 (그 외 포맷 0건)
 6-4-3) 시험종류 자동 태깅이 4종 + 기타 외 카테고리 없음
 6-4-4) 효능태그 1건 이상 매칭된 행 비율 ≥ 90%
 6-4-5) 편집자 계정에서만 입력 폼 노출
 6-4-6) 뷰어 계정에서 입력 시도 시 403 반환
 6-4-7) 다른 브라우저(Chrome / Edge) 동시 접속 시 신규 입력 60초 이내 양쪽 반영
 6-4-8) SharePoint 링크 새 탭에서 정상 열람 (편집자 본인 계정 기준)
 6-4-9) 모바일 화면(폭 390px)에서 레이아웃 깨짐 없음
 6-4-10) Apps Script 실행 시간 6분 한도 초과 없음 (171건 기준 GET 200ms 이내)

## 8. 미해결 의사결정 사항 (Phase 1 시작 전 확인)

 8-1) **신규 구글시트 vs 기존 엑셀 시트화**: 새로 만들지(권장) 기존 엑셀을 구글시트로 변환할지
 8-2) **편집자 그룹 정의**: 품질구매팀 구성원 이메일 리스트 또는 구글 그룹 주소
 8-3) **Apps Script 실행 계정**: 박영주 팀장 개인 계정 vs 팀 공용 계정(권장: 공용 계정으로 위임)
 8-4) **호스팅 방식**: Apps Script HtmlService로 통합 서빙 vs 별도 정적 호스팅(GitHub Pages 등)
 8-5) **SharePoint 링크 권한**: 타 부서원이 링크 클릭 시 SharePoint 자체 권한이 있는지 사전 확인 필요
